# 1.8.0 — Exponentiation

Exponentiation is an independently registered native Unique and is appended to the native reincarnation pool without replacing server entries. The passive requires a learned instance equipped in the active Tensura preset. An unfinished entry, ownership alone or an inactive preset does not activate it. It has no toggle, activation/upkeep cost or cooldown.

## Coverage and numeric policy

The [wiki](../../../wiki/pages/Additions-Exponentiation.md) lists every supported output and all 63 potentially changing attributes in the baseline runtime. The [machine-readable audit](exponentiation-attribute-audit.json) records the complete registered attribute policy, including exclusions and attributes bounded to 0–1. It is generated by the actual runtime registry test, rather than copied from assumed attribute IDs.

The operation is `x > 1 ? x*x : x`: fractional benefits, negative values and identity values remain unchanged. This preserves the user's beneficial-only choice. Native chance and item-stack limits remain enforced; finite overflow ceilings prevent infinity/NaN in ordinary positive output paths. Higher-is-harmful attribute metadata, costs, cooldowns, progression requirements and movement/body geometry are excluded. Gravity's elemental bonus is included; physical gravity and travel are excluded.

The passive does not rewrite arbitrary skill constants, private addon variables, recipe results, enchantment levels or inventory contents. Native percentage costs keep their formulas and can still depend on the current resource amount. This is broad native integration, not a claim that every unrelated addon damage/resource engine is intercepted.

## Avoiding repeated squares

A return-value lens on `AttributeInstance.getValue` leaves cached/raw attributes and saved bases untouched. Native player/mob attack calculations and Manas skill callbacks read ordinary damage inputs; the completed NeoForge damage amount is squared after Pre listeners, before absorption. Direct SHP damage is handled after native resistance/protection. Healing and resource hooks square positive deltas at their final storage writer, not the current total. Native source rates, sleep contributions, mining modifiers and point increments are read before their terminal output is squared.

Capacity queries at final writers use the empowered maximum. Regeneration must not clamp expanded reserves to an unempowered source capacity. Chained's native magicule ceiling is composed with the lens and retained. Native chance limits, skill requirements, learning/mode unlock branches and mastery ceilings remain authoritative.

Loading NBT is restoration, not healing. Unequipping removes the effective lens, clamps HP/SHP/aura/magicules and synchronizes the storage. It does not rewrite base attributes. Native earned base-pool awards remain earned. Fusion's effective-stat solver inverts the temporary lens once; forming, mirroring and restoring a fused body use transfer contexts rather than healing contexts.

## Verification

The clean build passes **188 native GameTests** and **30 unit tests**.

The supported baseline is Tensura 2.0.1.3 / NeoForge 21.1.209, Java 21. The release is built from a clean baseline compilation after the separate 2.0.1.4 / NeoForge 21.1.248 API compilation. This does not constitute a full Neo Otherworld runtime compatibility test.

Native gameplay coverage includes current-preset/learning gates, reincarnation eligibility, repeated reads and saved bases, movement-only exclusions, native mining/attack speed/chant speed, single-squared flat and melee damage, unchanged unattributed incoming damage, HP/SHP and energy deltas/costs, Schema healing, chance/finite limits, actual learning/mastery awards, XP/drop quantities, native EP split payouts, sleep/ordinary/SHP regeneration, Chained cap regressions and Fusion capacity/health transfer. Prior gameplay regressions remain in the suite.

The [opt-in real-client fixture](review-exponentiation/README.md) passed native Unique menu selection, translated name/icon, C2S slot equip/unequip, S2C capacity/attack-speed synchronization, unchanged movement, completed HP/aura gains, player and storage NBT loading without free refills, and normal capacity restoration/cleanup. Captures are real gameplay from a disposable copied save. Review classes are excluded from the shipped JAR.
